# Integrations (gaer-integrations)

All four are the same app and the same login. Data they share: **clips** (`/api/clips`) — text captured from a
page, a mail or a selection, inserted into Word/Outlook.

## /extension — browser extension (Chrome/Edge side panel)
- `extension/` is a plain MV3 extension (no build). The side panel iframes `<endpoint>/extension`.
  `/api/extension/download` zips it with the instance's address filled in (`__GAER_ENDPOINT__`).
- Bridge namespace `gaer-bridge` (`extension/sidepanel.js` ⇄ `web/src/bridge/extension.ts`): request/response
  with `id`; verbs `GET_VERSION`, `GET_PAGE_INFO`, `GET_PAGE_SNAPSHOT`, `GET_SELECTION`, `OPEN_URL`,
  `OPEN_OPTIONS`; push `TAB_CHANGED`. The panel only answers its endpoint's origin. Page content is read on
  demand with `chrome.scripting` — never a permanent content script.
- **Per-domain consent**: the app checks `/api/bridge-consent/check` before reading a page and asks the user.
- New verb: add a handler in `sidepanel.js` and a typed method in `bridge/extension.ts`.

## /office-addin — Office router
- Four XML manifests generated by `server/app/routes/office.py` (`/api/office/manifests/<app>.xml`), all pointing
  at `/office-addin?app=…` (Outlook adds `mode=read|compose`).
- `web/src/office/OfficeShell.tsx` is public (Office kills panes that do not initialise), loads Office.js,
  maps `Office.onReady` host → tool, and iframes `/extension/tools/word|outlook|document` (same origin).
- Protocol `gaer-office-host` (`bridge/officeHost.ts`): `hello` → `office-info`, `exec{id,type,payload}` →
  `result`. Commands are in `office/handlers.ts` and run one at a time.
- New command: add it to `handlers.ts` for the right host and call `exec("TYPE", payload)` from the tool.

## AI chat (optional)
- Off unless `AI_API_KEY` is set. `server/app/ai.py` calls an OpenAI-compatible endpoint (default OVHcloud AI
  Endpoints, `AI_MODEL`), streams it back as SSE events `delta`, `tool_calls`, `done`, `error`.
- Stateless: the client (`web/src/ai.tsx` `<Chat>`) keeps the conversation and sends it each time. Prompts and
  answers are never stored — only `ai_usage` (tokens), checked against the monthly limit per user (`/admin/ai`).
- Tools are client tools per surface (`TOOLS` in `ai.py`). The browser runs them — in Office through `exec()` —
  and sends the result back. To add one: declare it in `TOOLS[surface]`, handle it in the surface's `ToolRunner`.
- Context: the extension sends the page (only on allowed domains), Word the document text, Outlook the mail.

## Embedding and cookies
- `main.py` `EMBEDDABLE` + `csp_for()` allow `/extension`, `/office-addin`, `/login`, `/assets`, `/api`
  to be framed by extensions and Office hosts; everything else is `frame-ancestors 'self'`.
- In an iframe the client sends `X-Gaer-Embedded: 1`; the server sets a `SameSite=None; Partitioned` cookie.
  Passkeys in iframes need `allow="publickey-credentials-get *; publickey-credentials-create *"`.

## Public website — `/` and `/<slug>`
- Hosts: the app lives on `app.<domain>` (`ORIGIN`), the website on `<domain>` (`SITE_ORIGIN`, more hosts in
  `SITE_HOSTS`); one container answers both (`server/app/hosts.py`). On the app's host `/` → `/portal` and website
  pages → the website's host; on the website's host the app's paths → the app's host. Without `SITE_ORIGIN` both
  share one host. Redirects and canonical links are built from the settings, never from the `Host` header.
- `server/app/routes/web.py` renders `web_pages` (Markdown, sanitized with nh3) as HTML; da/en via `?lang`
  and the `w_lang` cookie; menu from `nav_order`. Edited in `/admin/web`. A slug may not be a path the app or
  server answers (`RESERVED_SLUGS`, from `routes.json`). Old `/w/…` links redirect (308). CSS/JS: `/static/w/…`.
- Links from the website to the app (`/login`, `/privatliv`) use `hosts.app_link()`; from the app to the website
  the frontend uses `config.site_url` (`/api/public/config`).
- The front page `/` is the Markdown page with an empty slug (default) or, with the setting `web_front =
  "facit246"` (chosen in `/admin/web`, `PUT /api/admin/web/front`; until then `WEB_FRONT` in the environment), the fixed "Facit · 246" story from
  `server/app/web_front.py` (da/en/de/sv/no, `Accept-Language` when nothing is chosen) with
  `web_static/facit.css` + `facit.js` (no inline scripts — CSP). Both end with the login card. Design: `specs/forside-246/`.
- `server/app/web_static/w.js` shows the consent banner and sends analytics — same storage keys as the app.

## /m — mobile app (PWA)
- `web/src/mobile/Mobile.tsx`: bottom tab bar (Hjem, Klip, Filer, Profil), camera upload, share.
- `web/public/m/manifest.webmanifest` and `web/public/m/sw.js` (scope `/m/`, never caches `/api/`).
